## How it works

Each database has a primary location and can serve reads from replicas; the Sessions API keeps a request's reads consistent with its own writes. Migrations are SQL files applied with Wrangler, locally and remotely. Queries are parameterised through `prepare().bind()`, which is also how injection is avoided.

## Where it fits

On this site D1 is the authoritative store for enquiries and their processing timeline. The rule we apply everywhere: D1 for records, KV for configuration, R2 for files.
